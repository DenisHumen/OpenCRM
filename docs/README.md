## Глоссарий

| Термин | Значение |
|---|---|
| **Клиент** | Запись в CRM: человек или компания, с которыми работает студия. Клиенты **не имеют** аккаунтов в системе. |
| **Сотрудник** | Пользователь системы с аккаунтом. Что ему можно — задаёт его роль. |
| **Роль** | Именованный набор прав, запись в базе, а не признак в коде. Пять готовых наборов — менеджер, бухгалтер, проджект-менеджер, гендиректор, наблюдатель — правятся под себя, и можно завести свои. Права строятся из реестра блоков: появился блок — появилась строка в матрице. |
| **Root** | Встроенный суперпользователь вне ролей. Всегда существует, все права есть всегда и отобрать их нельзя — иначе раздать доступ обратно стало бы некому. |
| **Менеджер** | Роль, помеченная «по умолчанию»: её получает новый сотрудник при регистрации. После установки это набор `manager` — ровно то, что умел сотрудник до появления ролей. |
| **Доска (board)** | Коллекция работ, оформленная для показа клиенту. Имеет заголовок, описание, обложку и набор работ. |
| **Работа (work)** | Единица контента на доске: изображение или видео + название и описание. |
| **Публичная ссылка (share link)** | Уникальный URL доски для клиента. Отзываемая, с опциональным сроком действия и PIN-кодом. Открывается без регистрации. |
| **Витрина (showcase)** | Публичная страница доски, которую видит клиент по ссылке. Лицо проекта. |
| **Заявка (deal)** | Работа для клиента от первого обращения до выдачи. Стержень системы: к ней привязываются этапы, бланки, заказы, списания со склада, звонки и письма. |
| **Этап (stage)** | Положение заявки в воронке. Название настраивается под бизнес, вид (`open` / `won` / `lost`) фиксирован — по нему считаются отчёты. |
| **Бланк (document)** | Бумага со сквозной нумерацией, своими статусами и снимком напечатанного. Видов четыре: квитанция приёмки (её половина остаётся у мастера, половина уходит клиенту), акт выполненных работ, заказ покупателя, заказ поставщику. |
| **Блок / модуль** | Часть системы, которую можно выключить целиком, не задев остальные. Реестр — `core/modules.py`, подробности — [11](11-modules.md). |
| **Диалог** | Переписка один на один между клиентом и ботом фирмы. Групп и каналов у этого канала нет по устройству; подробности — [13](13-telegram-messenger.md). |
| **Привязка** | Связь диалога с карточкой клиента: руками или сама, по точному совпадению номера. Похожего имени и похожего логина для этого не хватает. |
| **Живое состояние** | Присутствие сотрудников и шина событий поверх Redis: правка, сделанная одним, появляется у остальных сама. Устройство — [12](12-realtime.md). |
