# 01 — Обзор и концепция

## Что это

OpenCRM — система для студии дизайна/графики, решающая две задачи:

1. **Внутренняя CRM** — хранение данных о клиентах: контакты, заметки, история взаимодействий, файлы и документы. Рабочий инструмент менеджеров.
2. **Публичная витрина работ** — менеджер собирает доску с работами (изображения, видео), получает ссылку и отправляет её клиенту. Клиент открывает ссылку **без регистрации** и видит безупречно оформленное портфолио. Витрина — лицо студии перед клиентом.

## Роли

### Root (суперпользователь)

- Всегда существует в системе — создаётся автоматически при первом запуске (логин/пароль из конфигурации, при первом входе принуждается смена пароля).
- Полный доступ ко всему: клиенты, доски, файлы всех менеджеров.
- **Одобряет заявки на регистрацию сотрудников** — новый менеджер не может войти, пока root не подтвердит аккаунт.
- Управляет настройками сайта: название студии/бренд, логотип, контакты, ссылки на соцсети — всё, что показывается на витрине.
- Может деактивировать/удалять аккаунты менеджеров, сбрасывать пароли.

### Менеджер

- Регистрируется сам через форму, ждёт одобрения root.
- Ведёт клиентов: создаёт карточки, пишет заметки, фиксирует историю взаимодействий, прикрепляет файлы.
- Создаёт доски, загружает работы, настраивает порядок и оформление.
- Формирует публичные ссылки: генерирует, отзывает, ставит срок действия и PIN, смотрит статистику просмотров.
- Видит клиентов и доски. По умолчанию — всех (студия небольшая, работа общая); закреплённый менеджер у клиента отображается как «ответственный».

### Клиент (без аккаунта)

- Не регистрируется и не логинится. Вообще не знает о существовании CRM.
- Получает от менеджера ссылку вида `https://site.com/b/{token}`.
- Открывает витрину: смотрит работы, открывает их в полноэкранном просмотре, проигрывает видео.
- Если на ссылке стоит PIN — вводит его один раз (запоминается в сессии браузера).
- Если ссылка отозвана или истекла — видит аккуратную страницу «доступ закрыт» с контактами студии.

## Основные сценарии

### Сценарий 1: онбординг менеджера

1. Менеджер открывает `/register`, заполняет имя, email, пароль.
2. Видит экран «Заявка отправлена, ожидайте одобрения».
3. Root видит заявку в разделе «Сотрудники» → одобряет (или отклоняет).
4. Менеджер входит и работает.

### Сценарий 2: ведение клиента

1. Менеджер создаёт карточку клиента: имя/компания, телефон, email, мессенджеры, теги.
2. После звонка добавляет запись в историю: «Обсудили логотип, ждёт варианты к пятнице».
3. Прикрепляет к карточке бриф (PDF) и договор.
4. Вся хронология взаимодействий видна в карточке лентой, сверху — свежее.

### Сценарий 3: витрина для клиента (ключевой сценарий продукта)

1. Менеджер создаёт доску «Логотипы для кофеен», загружает 12 изображений и 2 видео.
2. Перетаскиванием выстраивает порядок, назначает обложку, пишет короткое описание доски.
3. Открывает «Поделиться»: генерирует ссылку, при желании включает PIN `4821` и срок действия 30 дней.
4. Жмёт «Посмотреть как клиент» — проверяет, как выглядит витрина.
5. Отправляет ссылку клиенту в мессенджер. Благодаря OG-разметке в чате разворачивается красивая карточка-превью с обложкой доски и названием студии.
6. Клиент открывает, смотрит, впечатляется.
7. Менеджер видит в CRM: доску открывали 3 раза, последний — сегодня в 14:02.

### Сценарий 4: отзыв доступа

1. Сделка не состоялась / доска устарела.
2. Менеджер отключает ссылку одним переключателем (или перегенерирует токен — старая ссылка умирает, появляется новая).
3. Клиент по старой ссылке видит вежливую страницу «Доступ к этой доске закрыт» с контактами студии.

## Функциональные требования (MVP)

### CRM
- [ ] Аутентификация сотрудников (email + пароль, сессии).
- [ ] Регистрация с одобрением root; root создаётся автоматически.
- [ ] CRUD клиентов: контактные данные, компания, теги, ответственный менеджер.
- [ ] Заметки и история взаимодействий (лента с типами: звонок, встреча, письмо, заметка).
- [ ] Файлы клиента: загрузка, скачивание, удаление (внутренние, на витрину не попадают).
- [ ] Доски: CRUD, загрузка работ (изображения + видео), drag-and-drop порядок, обложка.
- [ ] Публичные ссылки: генерация/отзыв/перегенерация, срок действия, PIN, счётчик и журнал просмотров.
- [ ] Раздел «Сотрудники» для root: заявки, одобрение, деактивация.
- [ ] Настройки сайта (root): бренд, логотип, контакты, соцсети.
- [ ] Профиль пользователя: смена пароля, выбор языка интерфейса (сохраняется в БД).
- [ ] Поиск по клиентам (имя, компания, телефон, email, теги).

### Витрина
- [ ] Публичная страница доски по токену, без регистрации.
- [ ] Экран ввода PIN (если включён).
- [ ] Страницы «ссылка отозвана/истекла» и «доска не найдена».
- [ ] Адаптивность: идеально на телефоне (клиенты чаще открывают ссылку из мессенджера).
- [ ] Полноэкранный просмотр работ (лайтбокс), навигация стрелками/свайпами.
- [ ] Видео: постер + воспроизведение по клику.
- [ ] OG-мета-теги: превью-карточка при отправке ссылки в мессенджеры.
- [ ] Учёт просмотров.

### Языки
- Интерфейс: английский по умолчанию, русский — переключается в профиле, выбор хранится в БД у пользователя.
- Витрина: язык оформления задаётся настройками сайта (контент работ — как загрузил менеджер).

## Нефункциональные требования

| Требование | Значение |
|---|---|
| Время открытия витрины | < 1.5 с до первого содержимого на мобильном 4G (превью генерируются заранее, ленивые загрузки) |
| Объём файла работы | до 200 МБ на файл (видео), лимит настраивается |
| Хранение файлов | локальная файловая система сервера, структура описана в [02-architecture.md](02-architecture.md) |
| БД | SQLite (MVP) → MySQL (рост); только переносимые типы и запросы через SQLAlchemy |
| Резервные копии | ежедневный дамп БД + файлы, см. [08-deployment.md](08-deployment.md) |
| Браузеры | последние 2 версии Chrome/Safari/Firefox/Edge; витрина обязана быть безупречна в мобильных WebView мессенджеров |

## Идеи на будущее (вне MVP, зафиксированы чтобы не потерять)

- **Сделки/заказы с воронкой статусов** (новый → в работе → на согласовании → завершён) и канбан-доской.
- **Реакции клиента на витрине**: «нравится / не нравится» на каждую работу без регистрации — менеджер видит, что зашло.
- **Комментарии клиента** к работам прямо на витрине (упростит согласование).
- **Уведомления менеджеру** (Telegram-бот/email): «клиент открыл доску», «новая реакция».
- **Несколько витринных тем** оформления доски на выбор менеджера.
- **Водяные знаки** на превью до подтверждения сделки.
- **Задачи и напоминания** для менеджеров.
- **Публичное общее портфолио студии** (не по ссылке, а постоянная страница-визитка с лучшими работами).
- **Аудит-лог** действий сотрудников для root.
- **Экспорт клиентов в CSV**.
