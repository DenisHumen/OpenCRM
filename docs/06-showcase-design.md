# 06 — Дизайн витрины

Витрина — лицо студии. Клиент получает ссылку в мессенджере, открывает — и за первые три секунды формирует впечатление о студии. Поэтому витрина обязана быть безупречной: быстрой, красивой, дорогой на ощупь. Этот документ — полное ТЗ на концепцию, поведение и анимации.

> **Статус: реализовано** по макетам [`design/Showcase.dc.html`](../design/Showcase.dc.html), `Pin.dc.html`, `Closed.dc.html`: SSR-шаблоны в `web/public/templates/` — masonry с серверной балансировкой колонок на три брейкпоинта, blurhash-плейсхолдеры (клиентский декодер без библиотек), ховер-подписи, лайтбокс, PIN-ячейки с автоотправкой, страница «доступ закрыт» с кнопками контактов. Отличие от ТЗ ниже: каскад появления работ идёт по задержке загрузки (как в макете), а не по скроллу; FLIP-разворачивание в лайтбокс заменено fade-in (по макету) — жест «свайп вниз для закрытия» остаётся идеей на будущее.

## Идея

**«Галерея, а не сайт».** Витрина ощущается как персональная выставка, собранная специально для этого клиента: минимум интерфейса, максимум работ. Ничего не отвлекает — ни меню, ни баннеры, ни «оставьте заявку» поверх экрана. Работы говорят сами.

Характер: просторный, спокойный, уверенный. Много воздуха, крупные изображения, сдержанная типографика, точные ненавязчивые анимации. Тёмная тема по умолчанию — работы на тёмном фоне выглядят как в галерее с приглушённым светом, цвета изображений «светятся».

## Структура страницы

```
┌─────────────────────────────────────────┐
│  ХЕДЕР                                  │  логотип студии (маленький, слева)
│                                         │
│  Название доски          ← крупно       │  из board.title
│  Описание доски          ← 1-2 строки   │  из board.description
│  n работ · обновлено «дата»  ← мелко    │
├─────────────────────────────────────────┤
│                                         │
│  ┌────┐  ┌──────────┐  ┌────┐           │
│  │    │  │          │  │    │           │  СЕТКА РАБОТ
│  └────┘  │          │  └────┘           │  masonry: колонки по ширине экрана
│  ┌──────┐└──────────┘┌───────┐          │  (3 — desktop, 2 — планшет, 1-2 — телефон)
│  │      │  ┌────┐    │       │          │  пропорции карточек = пропорции работ,
│  └──────┘  └────┘    └───────┘          │  без кадрирования
│                                         │
├─────────────────────────────────────────┤
│  ФУТЕР                                  │  название студии, контакты, соцсети
│  «Собрано в {бренд}» + логотип          │  всё из настроек сайта (root)
└─────────────────────────────────────────┘
```

- **Хедер минимален**: он представляет доску, а не студию. Брендинг студии — деликатно: маленький логотип сверху и полноценный блок контактов в футере, когда клиент уже посмотрел работы.
- **Masonry-сетка** — работы разных пропорций (логотипы квадратные, плакаты вертикальные, обложки горизонтальные) складываются в живую композицию без кадрирования. Порядок — тот, что задал менеджер перетаскиванием в CRM.
- **Карточка работы**: изображение + (если заданы) название и короткое описание, появляющиеся в подложке при наведении (desktop) или постоянной подписью под работой (mobile).
- **Видео в сетке**: постер-кадр с деликатной иконкой ▶ и длительностью в углу; на desktop при наведении — беззвучный зацикленный превью-фрагмент (если это будет дёшево по ресурсам — этап 2, MVP — постер).

## Анимации

Правило: анимации подчёркивают контент, а не показывают себя. Всё — короткое (150–400 мс), с естественными кривыми (`ease-out` на появление), прерываемое. При `prefers-reduced-motion` — все анимации отключаются, кроме простых fade.

1. **Появление страницы.** Хедер: название доски проявляется с лёгким подъёмом (fade + translateY 12px, 300 мс), описание — следом с задержкой 80 мс. Ощущение «занавес поднимается».
2. **Появление работ.** Карточки появляются каскадом по мере скролла (IntersectionObserver): fade + подъём 16px, 350 мс, задержка между соседними 40–60 мс. Каскад только при первом появлении, при обратном скролле работы уже на месте.
3. **Blurhash-переход.** До загрузки изображения карточка залита размытым цветовым пятном работы (blurhash из БД) — страница мгновенно «цветная», без белых дыр и скачков раскладки. Изображение проявляется поверх blurhash кросс-фейдом 250 мс.
4. **Наведение на карточку (desktop).** Изображение мягко приближается (scale 1.02, 300 мс), появляется градиентная подложка снизу с названием работы. Курсор — pointer. Никаких рамок и теней-взрывов.
5. **Открытие лайтбокса.** Карточка **разворачивается в полный экран из своего места в сетке** (shared element / FLIP-анимация, ~350 мс) — это самый дорогой на вид переход, он создаёт ощущение цельного пространства. Фон затемняется до почти чёрного.
6. **Листание в лайтбоксе.** Следующая работа въезжает горизонтальным слайдом с лёгким параллаксом подписи (250 мс). Свайпы на мобильном — с физикой инерции, резиновое сопротивление на краях.
7. **Закрытие лайтбокса.** Обратная FLIP-анимация — работа «улетает» на своё место в сетке. Также закрытие свайпом вниз на мобильном (изображение следует за пальцем, фон постепенно светлеет).
8. **Ввод PIN.** Поле по центру экрана, цифры появляются с микроскейлом; при ошибке — короткая горизонтальная тряска поля (200 мс) и деликатное сообщение. При успехе — экран PIN растворяется, и страница играет обычную анимацию появления.
9. **Футер.** Контакты студии проявляются каскадом при докрутке до конца — финальный аккорд: посмотрел работы → вот кто их сделал → вот как связаться.

## Лайтбокс (полноэкранный просмотр)

- Фон — тёплый почти чёрный (#0E0D0C c лёгкой прозрачностью и блюром задника).
- Изображение — максимально крупно с сохранением пропорций, отступы минимальны.
- Подпись: название + описание работы, полупрозрачной строкой внизу; скрывается по тапу по изображению (режим «только работа»).
- Управление: стрелки ←/→ (клавиатура и экранные, экранные видимы только при движении мыши), счётчик «4 / 14», крестик закрытия, Esc.
- Мобильный: свайпы влево/вправо — листание, свайп вниз — закрытие, двойной тап/щипок — зум изображения.
- Видео: нативный плеер с постером, автовоспроизведение после открытия в лайтбоксе (со звуком — клиент открыл осознанно), стандартные контролы.
- Предзагрузка соседних работ (±1) — листание без ожидания.

## Служебные экраны

Все служебные экраны — в том же стиле, с логотипом и контактами студии. Клиент никогда не должен увидеть «голую» ошибку.

| Экран | Содержание |
|---|---|
| **Ввод PIN** | Логотип студии, «Эта подборка защищена кодом», ячейки для цифр, подсказка «Код вам отправил менеджер». Ничего о содержимом доски не раскрывается (ни названия, ни обложки).<br>Ячеек ровно столько, сколько введено цифр, минимум 4 — пустая «запасная» ячейка читалась бы как незаполненное обязательное поле. Код разрешён длиной 4–8 цифр, а его длину клиенту не сообщают, поэтому форма отправляется не на 4-й цифре, а через 450 мс после остановки ввода (продолжение набора сбрасывает таймер; Enter отправляет сразу). После неверной попытки поле очищается |
| **Доступ закрыт** | Единый экран для отозванной/истёкшей/неопубликованной/несуществующей ссылки (причину не раскрываем): «Доступ к этой подборке закрыт», контакты студии, «Свяжитесь с нами — пришлём актуальную ссылку» |
| **Пустая доска** | «Работы скоро появятся» — на случай, если менеджер поделился ссылкой раньше времени |

## OG-превью ссылки (то, что видно в мессенджере до клика)

Первое касание клиента — карточка ссылки в чате. Сервер отдаёт:

- `og:title` — название доски;
- `og:description` — описание доски или «Подборка работ {бренд}»;
- `og:image` — обложка доски (карточка `card.webp` обложечной работы; при отсутствии — дефолтная OG-картинка из настроек);
- `og:site_name` — название студии.

Для досок с PIN в `og:image` идёт **нейтральная брендированная картинка** (не обложка) — содержимое защищённой доски не должно светиться в чате.

## Производительность (часть дизайна)

- SSR первого экрана + blurhash: страница видна мгновенно, изображения догружаются лениво (`loading="lazy"`, `srcset` с card/large версиями).
- Все превью — WebP, сгенерированы заранее при загрузке работы; оригинал клиенту не отдаётся никогда (только large 1920px).
- Шрифты — self-hosted, `font-display: swap`, максимум 2 начертания.
- Цель: LCP < 1.5 c на мобильном 4G, CLS = 0 (blurhash-плейсхолдеры резервируют место точно по пропорциям работы).

## Дизайн-токены витрины (стартовая точка для Claude Design)

Витрина — та же тёплая тёмная семья, что и CRM (см. палитру в [05-crm-design.md](05-crm-design.md)), но темнее и «галерейнее»: фон глубже, интерфейса меньше, работы ярче.

```
Фон:            #161514 (тёплый графит глубже, чем фон CRM #262624; не чистый чёрный)
Поверхности:    #201F1D (PIN-форма, служебные экраны)
Текст основной: #F5F4EF (тёплый белый — общий с CRM)
Текст вторичный:#9C998F
Акцент:         задаётся брендом студии в настройках (по умолчанию тёплый коралл #D97757)
Лайтбокс:       фон #0E0D0C с лёгким блюром задника
Радиусы:        карточки 12px, кнопки 10px
Типографика:    заголовок доски — антиква display (clamp 32–56px), как заголовки CRM —
                единая фирменная деталь; текст — гротеск 16px/1.6, подписи — 13–14px
Сетка:          контейнер max 1440px, отступы 24px (mobile) / 48px (desktop),
                gap сетки работ 16–24px
```

Токены живут в `web/frontend/shared/tokens` и синхронизируются с макетами Claude Design.
