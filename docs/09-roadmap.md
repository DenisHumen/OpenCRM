# 09 — План работ

> **Статус на 31.07.2026:** этапы 0–5 завершены; этап 6 — артефакты готовы и проверены полным
> развёртыванием на Ubuntu 24.04, ждёт боевого VPS с реальным доменом.
> Реализация подтверждена 442 тестами (интеграционные, инварианты сетки, автообновление,
> конфигурация развёртывания) и живыми прогонами в браузере (CRM и витрина).

Порядок выстроен так, чтобы каждый этап заканчивался работающим, проверяемым результатом. Ключевой продуктовый риск — витрина («лицо проекта»), поэтому вертикальный срез «доска → ссылка → витрина» появился максимально рано.

## Этап 6 — Production 🔶 (артефакты готовы, ждёт VPS)

- [x] `docker/Dockerfile` (multi-stage: node → python + ffmpeg), `docker-compose.yml` (app + nginx + certbot, состояние в домашнем каталоге), `nginx/templates/` (медиа напрямую, блок оригиналов, лимиты, HTTP/HTTPS-варианты).
- [x] Бэкапы: `scripts/backup.sh` (ежедневные + еженедельные, ротация) и `scripts/restore.sh`.
- [x] Очистка мягко удалённого: `scripts/purge_deleted.py` (карантин 30 дней, `--dry-run`).
- [x] Перенос на MySQL: `scripts/migrate_to_mysql.py` (по [03-database.md](03-database.md)).
- [x] `/healthz` + healthcheck в compose.
- [x] Автообновление из GitHub: демон на хосте (`deploy/`, `scripts/autoupdate.py`) опрашивает ветку
      и передеплоивает сам. Тесты нового кода до подмены (этап `tests` в Dockerfile), снимок базы
      до миграций, health-check живыми страницами, автоматический откат с возвратом базы, журнал
      обновлений и уведомления в Telegram. Упавший коммит не пробуется по кругу. CI на push/PR —
      `.github/workflows/tests.yml`. См. [08-deployment.md](08-deployment.md), регрессии —
      `tests/test_autoupdate.py`.
- [x] `opencrm.sh` — установка одной командой и меню управления: сам ставит Docker, генерирует
      секреты, подставляет UID:GID, поднимает стек, проверяет A-запись перед выпуском сертификата
      и включает автообновление (systemd, а без него cron). Повторный запуск секреты не трогает.
      Проверено полным развёртыванием на Ubuntu 24.04 (26 проверок: сайт, вход, идемпотентность,
      команды, меню). Попутно закрыт `.dockerignore` — контекст сборки упал с ~230 МБ до 6 КБ,
      а `config/.env` перестал запекаться в слой образа.
- [x] Флаг `Secure` у cookie — по схеме `OPENCRM_BASE_URL`, а не по имени окружения. Раньше
      документированный сценарий «локальная сеть без домена» ломался вчистую: вход возвращал 200,
      браузер выбрасывал Secure-cookie, пришедшую по HTTP, и человека сразу выкидывало обратно.
      См. [07-security.md](07-security.md), регрессии — `tests/test_config.py`.
- [x] Обвязка сервера в мастере установки: ufw (порт SSH ищется по подключению, слушающим
      сокетам и конфигу — на Ubuntu 24.04 ssh поднимается сокетом systemd, и `sshd_config`
      может врать), ежедневные копии таймером systemd (раньше скрипты бэкапа были, а запускать
      их было некому), предел на логи контейнеров, проверка памяти и места перед сборкой.
      См. [07-security.md](07-security.md), [08-deployment.md](08-deployment.md).
- [x] Страница обслуживания на время обновления: nginx отдаёт её вместо «502 Bad Gateway»,
      503 + `Retry-After`, самовозврат на сайт. Собственные ошибки приложения не подменяются,
      проверка Let's Encrypt продолжает работать. Змейка с таблицей лидеров из задачи —
      отдельно, ещё не сделана.
- [x] Адрес приложения nginx перечитывает на каждом запросе (`resolver` + переменная в
      `proxy_pass`). Без этого пересозданный при обновлении контейнер получал другой адрес,
      а nginx до перезапуска стучался по старому: сайт лежал при живом приложении, и откат
      автообновления краснел ровно по той же причине. Регрессии — `tests/test_deploy_config.py`.
- [ ] Развёртывание на боевом VPS: реальный домен, HTTPS (Let's Encrypt), прогон чек-листа из [07-security.md](07-security.md).
- [ ] Внешний uptime-мониторинг (алерт на заполнение диска уже есть внутри приложения).
- [x] Репетиция восстановления из бэкапа: на стенде Ubuntu 24.04 заведён клиент через API,
      снята копия, данные испорчены, восстановление сделано через меню — лишняя запись исчезла,
      запись из копии на месте, прежняя база отложена в `*.before-restore-*`, сайт поднялся сам.

## После MVP (по приоритету пользы)

1. Реакции клиента на работы (👍/👎) + уведомления менеджеру.
2. Секции внутри доски.
3. Сделки/заказы со статусами и канбаном.
4. Комментарии клиента на витрине.
5. Переезд на MySQL (по факту роста — скрипт готов).
6. Темы витрины, общее публичное портфолио студии, аудит-лог, экспорт CSV.
7. Раздел «Аналитика» (пункт сайдбара зарезервирован).
8. Self-hosted шрифты (сейчас Google Fonts — заменить перед продакшеном при требованиях приватности).
