# 09 — План работ

> **Статус на 24.07.2026:** этапы 0–5 завершены; этап 6 — артефакты готовы, ждёт развёртывания на VPS.
> Реализация подтверждена 89 интеграционными тестами и живыми прогонами в браузере (CRM и витрина).

- [x] Служебные экраны по макетам: PIN из ячеек с автоотправкой и shake-ошибкой, «доступ закрыт» с кнопками контактов, пустая доска.

- [ ] Формальный прогон Lighthouse (LCP < 1.5 c mobile) — на реальном хостинге; архитектурно заложено (SSR, blurhash, WebP, immutable-кэш).

- [x] Регистронезависимый поиск для кириллицы (подмена `lower()` в SQLite, см. [03-database.md](03-database.md)).
- [x] Контроль свободного места: карточка «Хранилище» на дашборде, баннер в сайдбаре, раздел «Обслуживание» с очисткой корзины, блокировка загрузок при нехватке места. Работает без прав root (`statvfs`), Ubuntu и Fedora одинаково.
- [x] Удаление публичной ссылки (`DELETE /shares/{id}`) с явным разделением: ссылка ≠ файлы доски.
- [x] Аудит безопасности (эксплуатация + закрытие, см. [07-security.md](07-security.md)): закрыт обход

      Регрессии — `tests/test_security.py`.
- [x] Настройки: удаление логотипа и OG-картинки (сброс к дефолту, файл стирается с диска).
- [x] Удаление доски уносит файлы работ сразу (доски невосстановимы; каскад БД + чистка диска),

      размером на диске, датой загрузки и последним просмотром, точечное удаление. Регрессии — `tests/test_files.py`.
- [x] Аватары пользователей (self-upload в профиле, обрезка в квадрат webp, SVG не принимается) +
      присутствие: онлайн/офлайн и «последний раз в сети» (`last_seen_at` на пользователе, heartbeat
      фронта, порог 150 c). Показ — профиль, сайдбар, список сотрудников. Регрессии — `tests/test_profile.py`.
- [x] Управление сотрудниками (root): смена роли `manager ↔ root` (администраторов может быть несколько,
      последний root и своя роль защищены) и окончательное удаление аккаунта (сессии — каскадом, авторство
      в клиентах/досках/заметках обнуляется, а не пропадает). Регрессии — `tests/test_staff_roles.py`.

## После MVP (по приоритету пользы)

1. Реакции клиента на работы (👍/👎) + уведомления менеджеру.
2. Секции внутри доски.
3. Сделки/заказы со статусами и канбаном.
4. Комментарии клиента на витрине.
5. Переезд на MySQL (по факту роста — скрипт готов).

8. Self-hosted шрифты (сейчас Google Fonts — заменить перед продакшеном при требованиях приватности).

## Definition of Done (для каждого этапа)

- Код соответствует границам слоёв из [02-architecture.md](02-architecture.md).
- Сервисы покрыты unit-тестами, API — интеграционными (happy path + основные ошибки).
- Миграции накатываются на чистую БД и на БД предыдущего этапа.
- UI проверен на en и ru, на desktop и мобильном.
- Документация обновлена, если этап изменил контракты.
