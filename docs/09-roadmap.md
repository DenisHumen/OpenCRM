# 09 — План работ

Порядок выстроен так, чтобы каждый этап заканчивался работающим, проверяемым результатом. Ключевой продуктовый риск — витрина («лицо проекта»), поэтому вертикальный срез «доска → ссылка → витрина» появляется максимально рано.

## Этап 0 — Каркас проекта

- [ ] Структура каталогов по [02-architecture.md](02-architecture.md), `pyproject.toml`, lock-файлы.
- [ ] FastAPI-приложение, конфиг из env (Pydantic Settings), логирование.
- [ ] SQLAlchemy + Alembic, первая миграция (users, site_settings), фабрика сессий.
- [ ] Bootstrap root-аккаунта при первом запуске.
- [ ] Vite + React + TypeScript + Tailwind; дизайн-токены в `shared/`.
- [ ] Dev-запуск одной командой; линтеры (ruff, eslint), pytest-скелет.

**Готово, когда:** проект стартует локально, root создан, `/healthz` зелёный, тесты запускаются.

## Этап 1 — Аутентификация и сотрудники

- [ ] Вход/выход, серверные сессии, CSRF, rate limit на вход.
- [ ] Регистрация менеджера → статус `pending` → экран ожидания.
- [ ] Раздел «Сотрудники» для root: заявки, одобрение/отклонение, деактивация, сброс пароля.
- [ ] Принудительная смена пароля (root при первом входе, после сброса).
- [ ] Профиль: имя, смена пароля, переключение языка (en по умолчанию, выбор — в БД).
- [ ] Каркас i18n (en/ru) в SPA и серверных страницах.

**Готово, когда:** менеджер проходит полный цикл регистрация → одобрение → вход → смена языка, всё покрыто интеграционными тестами.

## Этап 2 — CRM: клиенты

- [ ] CRUD клиентов, список с поиском и фильтрами (имя/компания/телефон/email/теги).
- [ ] Карточка клиента: inline-редактирование контактов, вкладки.
- [ ] Лента истории: заметки/звонки/встречи/письма, быстрое добавление.
- [ ] Файлы клиента: загрузка (magic-bytes валидация), скачивание через сессию, удаление.
- [ ] Мягкое удаление + восстановление root'ом.

**Готово, когда:** менеджер ведёт клиента целиком из UI; файлы недоступны без сессии.

## Этап 3 — Доски и медиапайплайн

- [ ] CRUD досок; привязка к клиенту (опционально); черновик/публикация.
- [ ] Загрузка работ: multipart, статус `processing`, фоновая генерация large/card/thumb WebP + blurhash (Pillow).
- [ ] Видео: приём mp4/webm, постер через ffmpeg, длительность.
- [ ] Редактор доски: сетка миниатюр, drag-and-drop порядок (шаг sort_order), выбор обложки, названия/описания работ, мультизагрузка перетаскиванием с прогрессом.
- [ ] Удаление работы с очисткой файлов.

**Готово, когда:** доска из 20 смешанных работ собирается в UI за минуты, превью корректны, порядок сохраняется.

## Этап 4 — Публичные ссылки и витрина (сердце продукта)

- [ ] Модель ссылок: генерация токена, отзыв, перегенерация, срок действия, PIN (bcrypt + rate limit + cookie доступа).
- [ ] Блок «Поделиться» в редакторе доски: копирование URL, переключатель активности, опции, «Посмотреть как клиент».
- [ ] Витрина `/b/{token}`: SSR-шелл с OG-тегами, masonry-сетка, blurhash-плейсхолдеры, ленивая загрузка.
- [ ] Лайтбокс: FLIP-открытие, листание (клавиатура/свайпы), видео, зум на мобильном.
- [ ] Анимации по [06-showcase-design.md](06-showcase-design.md), `prefers-reduced-motion`.
- [ ] Служебные экраны: PIN, «доступ закрыт», пустая доска.
- [ ] Учёт просмотров (хэш IP) + статистика в CRM.
- [ ] Прогон производительности: LCP < 1.5 c на mobile, CLS = 0.

**Готово, когда:** ссылка, отправленная в Telegram, разворачивается карточкой с обложкой; витрина открывается мгновенно и безупречно выглядит на телефоне; отзыв ссылки срабатывает немедленно.

## Этап 5 — Настройки сайта и полировка

- [ ] Настройки root: бренд, логотип, контакты, соцсети, язык витрины, дефолтная OG-картинка.
- [ ] Дашборд CRM: последние клиенты/доски, сводка просмотров.
- [ ] Пустые состояния, подтверждения опасных действий, тосты, обработка ошибок всюду.
- [ ] Сквозной прогон дизайна CRM по дизайн-нотам (скриншот) и макетам Claude Design.

## Этап 6 — Production

- [ ] Dockerfile (multi-stage), docker-compose, конфиг nginx (media, лимиты, HTTPS, HSTS, CSP).
- [ ] Бэкапы (cron) + отрепетированное восстановление.
- [ ] `/healthz`, внешний uptime-мониторинг, алерт на диск.
- [ ] Развёртывание на VPS, прогон чек-листа безопасности из [07-security.md](07-security.md).

**Готово, когда:** продакшен живёт на домене с HTTPS, бэкап восстановлен на тестовой копии.

## После MVP (по приоритету пользы)

1. Реакции клиента на работы (👍/👎) + уведомления менеджеру.
2. Секции внутри доски.
3. Сделки/заказы со статусами и канбаном.
4. Комментарии клиента на витрине.
5. Переезд на MySQL (по факту роста).
6. Темы витрины, общее публичное портфолио студии, аудит-лог, экспорт CSV.

## Definition of Done (для каждого этапа)

- Код соответствует границам слоёв из [02-architecture.md](02-architecture.md).
- Сервисы покрыты unit-тестами, API — интеграционными (happy path + основные ошибки).
- Миграции накатываются на чистую БД и на БД предыдущего этапа.
- UI проверен на en и ru, на desktop и мобильном.
- Документация обновлена, если этап изменил контракты.
